# 叙事架构与钩子引擎

仅在新写、扩写、压缩或重新搭建口播结构时读取。

## 一句话母命题

母命题不是“这条视频讲什么”，而是“观众看完会改变哪一个判断”。先完成：

> 多数人把 ___ 理解成 A；证据显示真正决定结果的是 B；这会让 ___ 付出/得到 C。

再写一个全文追问：观众为什么值得看到最后？无法回答时，继续研究或缩小选题。

## 钩子候选机制

至少跨4种机制生成6–10个候选：

1. **可验证反转**：具体事实 → 常见预判 → 立刻纠偏。
2. **结果前置**：先展示损失、成果或异常结果，再倒推原因。
3. **隐藏代价**：表面获得A，实际支付B。
4. **双真相碰撞**：两个都成立的事实却导向冲突结论。
5. **人群点名**：只筛选真正相关的人，并说清他们将失去或获得什么。
6. **场景开门**：从正在发生的动作、决定或瞬间进入。
7. **标准错位**：大家用A衡量，真正该看的是B。
8. **反方先行**：先承认最强反例，再揭示它遗漏的条件。

好钩子通常包含“具体对象 + 预期违背 + 利益/代价”，但不必每句都套固定语法。

### 评分

每项0–2分，总分10分：

- 具体：有没有人物、动作、数字、物件或明确对象？
- 意外：是否真正违背目标观众的默认判断？
- 相关：这件事为什么与目标观众有关？
- 可信：不用夸张和假数字是否仍成立？
- 兑现：正文前四分之一能否回答它？

平分时选更容易说出口、更容易配首帧画面的版本。钩子吸引错人会导致更早离开，因此范围准确比“人人都想点”重要。

### 首句遮盖测试

把第二句及之后全部遮住，只读首句：最强且可证的冲突、收益或代价是否已经出现？如果第二句单独读明显更强，就把它前置或与首句合并。陌生品牌、论文和技术缩写会产生“名词税”；名称不是热点本身时，先交代人能理解的矛盾，再揭晓对象。不要把这个测试误用成“所有首句都不能出现产品名”。

### 三轨首帧（仅导演稿）

- **画面**：展示结果、动作或证据，不拍无意义走路和摆手。
- **屏幕文字**：补充关键词、数字或代价，不逐字抄口播。
- **口播**：承载矛盾和信息缺口。

三轨必须指向同一个承诺。

## 按题材选择弧线

### 新闻/事件型

异常事实 → 纠正标题党或遗漏背景 → 解释机制 → 谁受益/谁承担成本 → 个人判断 → 公平问题。

适合公共事件、行业新闻、规则变化。不要把时间线复述成新闻联播；只保留能改变判断的节点。

### 案例拆解型

结果 → 常见误读 → 一个可视化细节 → 证据递进 → 边界 → 更大的判断。

适合产品、游戏、公司、创作者和商业案例。细节必须解释“为什么”，不是单纯猎奇。

### 观点辩论型

鲜明结论 → 最强反方为什么有道理 → 其遗漏的条件 → 真实代价 → 立场升级。

适合争议选题。反方要用它最强的版本；这样观点更可信，也更容易产生高质量评论。

### 知识/产品型

常见错误 → 原理 → 参数或概念转成生活场景 → 选择成本 → 可执行判断。

避免参数清单。每个参数都要完成“参数 → 场景 → 对人的影响”。不能假装亲自使用过。

### 个人故事型

代价/结果前置 → 原先错误 → 错误升级的具体场景 → 决策转折 → 结果边界 → 新判断。

情绪来自选择和代价，不能擅自添加家庭冲突、疾病、负债或其他戏剧经历。

## 时长与节拍

节拍是一次认知变化，不等于一个句号或一次剪辑。

| 目标时长 | 有效节拍参考 | 结构重点 |
|---|---:|---|
| 30–45秒 | 3–4 | 钩子、一个证据、一个判断、一个问题 |
| 60秒 | 4–6 | 冲突、原因、场景、结论 |
| 90秒 | 6–8 | 增加反方和边界 |
| 120秒 | 7–9 | 完整机制、场景、受众收益与一个关键边界 |
| 150秒 | 8–10 | 完整证据递进、机制解释、反方与价值碰撞 |

150秒可先按比例预算：

- 0–3秒：钩子。
- 3–15秒：代价或核心疑问。
- 15–40秒：事件/案例与第一次证据。
- 40–65秒：第一轮反转。
- 65–100秒：机制、场景或数据解释。
- 100–125秒：最强反方、限制或第二轮反转。
- 125–140秒：个人判断升级。
- 140–150秒：一个中心评论问题。

比例可因题材改变。每10–20秒应有新事实、反转、场景、后果或问题，但不要为了合格硬塞信息。

120秒可把0–3秒留给钩子，前18秒完成第一次兑现与受众关联，随后用具体场景、机制和反转推进，在最后约20秒压缩边界、升级判断并只留一个评论题。它是预算参考，不是固定模板。

## 留存工具

- **兑现后再升级**：回答开头问题后，提出更深一层的问题；不要一直拖着不回答。
- **抽象落地**：每两个抽象判断至少换成一个具体动作、场景或后果。
- **证据递进**：个案细节 → 外部数据 → 边界/反方，或按最能说服该受众的顺序调整。
- **语言对照**：可用“表面/实际”“得到/付出”“个人/机构”，但同一模板不要反复出现。
- **压缩背景**：凡是不改变观众判断的时间、履历和定义都删除。
- **单一主情绪**：惊叹、愤怒、焦虑、希望、爽感或好奇择一；次情绪只作转折。
- **前段关联**：泛受众稿前20%应让非从业者知道这件事会改变什么；垂直稿则交代目标受众的具体收益或代价。
- **术语解码**：一个节拍默认只引入一个陌生概念，术语后紧跟白话后果。多个品牌或缩写只证明“生态很大”却不改变判断时，压成一个类别。

## 评论问题

评论题应与内容类型匹配：

- 实用/知识内容：选择、方法、判断边界。
- 体验/故事内容：亲历、感受、偏好。
- 观点内容：双场景标准测试或不可兼得的取舍。
- 产品内容：明确预算、场景或机会成本下的选择。

把“你怎么看”改成能立刻回答、但解释后能分出立场的问题。例如：

- 同样的做法，个人用于跨过门槛和大公司用于压缩岗位，应该用同一标准吗？
- 预算相同，你选更强参数还是更稳体验？为什么？
- 到哪一步，你会认为便利已经不值得这个代价？

目标是泛受众时，再做一次“非从业者代理测试”：没有用过该产品、也不从事该职业的人，能否在几秒内按自己的价格、体验、公平、风险或选择成本站队？如果不能，问题过窄。垂直账号可以保留专业身份题，只要这正是目标评论人群。

结尾只留一个站队轴。两个连续问句即使都相关，也会分散第一条评论该回答什么；把次要问题改成陈述条件，或合并为一个二选一。正文中的解释性反问不受此限制。

只问一个主问题。若用户要3条评论区话术，分别承担站队、亲历和边界，不重复同一句。

## 常见改稿模式

- **钩子变强**：重做前15秒，同时检查正文能否兑现；不能只夸大首句。
- **扩到指定时长**：增加证据、具体场景、机制、最强反方或现实后果，不重复母命题。
- **压缩**：保留母命题、最强证据和评论问题；先删背景与第二支线。
- **去AI味**：删除泛化开场、总结腔、对称排比和重复转折词；补真实判断与具体名词。
- **增加数据**：只加入能改变判断的数字，并说明来源口径与意义。
- **参考爆款复刻**：提取情绪机制、证据顺序和节拍，不复制原句、故事细节或独特表达。
